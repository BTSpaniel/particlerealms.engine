# MorphField JSON contracts

This directory is the machine-readable boundary for MorphField's canonical,
device-independent JSON. Every schema uses JSON Schema Draft 2020-12, declares
an absolute versioned `$id`, and is checked against the Draft 2020-12
metaschema plus a local reference registry.

## Schema catalog

| Schema | Canonical instance |
| --- | --- |
| `common.schema.json` | Shared version, transform, material, motion, collision, intent, simulation, and recursive JSON definitions. |
| `source.schema.json` | The nine semantic Nexel source kinds. |
| `nexel.schema.json` | One normalized semantic Nexel descriptor. |
| `scene.schema.json` | `NexelScene.toJSON()` and the authoritative `.morph` `MANF` chunk. |
| `patch.schema.json` | One normalized monotonic Nexel patch. |
| `nexel-capabilities.schema.json` | The versioned implementation capability profile. |
| `nexel-capability-report.schema.json` | One result from `inspectNexelCapabilities()`. |
| `particle-chain-simulation.schema.json` | Strict metadata for the production particle/PhysicsChain Nexel snapshot adapter. |
| `benchmark-receipt.schema.json` | A copyable Playground benchmark receipt with explicitly sourced timing channels. |
| `validation-report.schema.json` | The exported browser validation-console result. |
| `provenance.schema.json` | The canonical versioned object stored in an optional `.morph` `PROV` chunk. |
| `bundle.schema.json` | The generated offline compound document containing every other schema resource under `$defs`. |

`nexel-capabilities.json` is the checked static capability instance. The public
ES-module profile is generated independently from Engine constants and browser
tests reject drift between the two.

`bundle.schema.json` is generated by `python tools/build_morphfield_schemas.py`.
Its embedded resources retain their original absolute `$id` and `$schema`
values, so references resolve the same way online and offline. `--check` fails
when the committed bundle is stale. Release-site builds copy the canonical
files byte-for-byte to `/schemas/morphfield/v2/`; schema source is never
recreated inside the bundler.

For local validation, install the bounded test dependencies from
`tests/morphfield/requirements.txt`, then run:

```bash
python tools/validate_morphfield_json.py scene.json
python tools/validate_morphfield_json.py patch.json --schema patch
python tests/morphfield/run_python_tests.py
```

The validator resolves only the local catalog and rejects duplicate object
names, NaN/Infinity, invalid UTF-8, oversized input, excessive nesting, and
excessive node counts before schema evaluation.

## What is not JSON

JSON Schema is not used to pretend that runtime object graphs are portable
data. These contracts remain explicit binary or JavaScript/WebGPU ABIs:

| Contract | Real representation |
| --- | --- |
| `.morph` header, directory, compressed chunks, and CRCs | Versioned little-endian binary container. The semantic `MANF` payload uses `scene.schema.json`; optional canonical `PROV` metadata uses `provenance.schema.json`. |
| Compiled scenes and compiled patches | Device-independent JavaScript records containing typed arrays, strict runtime ABI validation, and compiler-origin or deterministic snapshot-requalification checks. |
| Fieldlet headers, certificate pools, spatial records, query records | Fixed little-endian and WGSL buffer layouts with byte/word constants, whole-batch admission, and ABI tests. |
| Renderer creation, `encode()` targets, outputs, and device replacement | Runtime contracts containing borrowed WebGPU objects and host-owned views. |
| Renderer statistics and diagnostics | Read-only runtime telemetry, not an authoritative asset format. |

Simulation records deliberately have a strict core envelope (`adapter` and an
optional `authoritative`/`visual` authority) plus adapter-owned canonical JSON.
Adapter-specific payload schemas can therefore be added without changing the
Nexel schema.

## Canonical versus convenient input

Runtime authoring accepts a small set of documented conveniences, such as a
scalar oriented-sample radius or `collision: true`. The compiler immediately
normalizes them. Persisted scenes, `.morph` manifests, capability reports,
receipts, validation reports, and schema fixtures use only the strict
canonical form and reject unknown core keys.
Normalized patches always carry their canonical `$schema`, schema name, and
version. Capability documents expose an explicit `compilerMode` and one
`gpuQueryModes` entry for each of the six typed queries; omitted support is
never treated as implied support.
Semantic runtime validation remains authoritative for constraints that JSON
Schema cannot express completely, including quaternion normalization, rigid or
uniform-scale transforms, bounds ordering, grid-product equality, index ranges,
CSG depth/cycles, certificate derivation, f32 conservatism, and GPU ABI offsets.

The schemas follow the official [JSON Schema specification](https://json-schema.org/specification),
Draft 2020-12's [compound-document bundling rules](https://json-schema.org/draft/2020-12/json-schema-core#section-9.3.1),
and the official [language-independent conformance suite](https://github.com/json-schema-org/JSON-Schema-Test-Suite).
