Core runtime & GPU abstractions

These terms cover the low-level building blocks that everything else in Engine v2 sits on.

WebGPU

Definition Browser GPU API used for all rendering and compute in Engine v2. Replaces WebGL/Three.js and has no software fallback.

Example 
const adapter = await navigator.gpu.requestAdapter();
if (!adapter) throw new Error('WebGPU not available');
const device = await adapter.requestDevice();
console.log(device.limits.maxTextureDimension2D);

Framegraph

Definition Graph of render/compute/copy passes and virtual resources. Schedules passes automatically based on read/write dependencies.

Example

const color = fg.createTexture({ name: 'mainColor' });

fg.addRenderPass('clear', pass => {
  pass.write(color, { loadOp: 'clear' });

Frame loop

Definition Main browser loop that calls beginFrame() → buildGraph() → execute() → present() every animation frame and wires timing into ECS/net.

Example 
function frame(ts) {
  engine.beginFrame(ts);
  engine.buildFramegraph();
  engine.executeFramegraph();
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);

GPU Resilience

Definition Production-grade patterns for handling GPU device loss, crash recovery, graceful shutdown, and error management. Based on toji.dev best practices.

Device Loss The GPU driver can crash, be killed by Chrome's watchdog (10s timeout), or lose power. When this happens, all GPU resources (buffers, textures, pipelines) are destroyed and the device becomes unusable.

Auto-Recovery (GpuRecovery.js) Listens for device.lost, then automatically requests a new adapter + device with exponential backoff. Reconfigures the canvas context and fires callbacks so the app can re-upload resources. Chrome limits: 2nd crash in 2 min blocks adapter for the page; 3rd blocks all pages.

Example — Recovery Setup 
import { GpuRecovery } from 'engine/core/gpu/GpuRecovery.js';

const recovery = new GpuRecovery({
    device,
    canvas,
    context,
    format: navigator.gpu.getPreferredCanvasFormat(),
    onLost: () => { renderLoop.pause(); },
    onRecovered: ({ device }) => {
        myDevice = device;
        recreateResources();
        renderLoop.resume();
    },
    onRecoveryFailed: () => {
        showMessage('Please refresh the page');
    },
});

// Test: recovery.simulateLoss();

Graceful Shutdown Call device.destroy() before page unload to release GPU memory cleanly. This prevents Chrome from counting it as a crash. The engine does this automatically via beforeunload.

Example — Shutdown 
// GpuDevice.destroy() handles:
// 1. Flush pending GPU work
// 2. Destroy pipeline cache, buffer pool, scheduler
// 3. Call device.destroy() (releases all GPU memory)
// 4. Clear event listeners

gpuDevice.destroy();

Error Handling

  • uncapturederror event — global listener on GPUDevice catches all unhandled validation/OOM/internal errors
  • event.preventDefault() — suppresses DevTools console warnings (Chrome 128+, may be no-op on Firefox/Safari)
  • SharedTextureMemory/SharedImageD3D errors — Chrome-only D3D11 swap chain bug, silently filtered
  • Render loop try-catch — catches JS exceptions in renderFrame() with auto-pause after 5 consecutive failures

Canvas Resize Use devicePixelContentBoxSize from ResizeObserver for pixel-perfect sizing (falls back to contentBoxSize × dpr on older Safari). Clamp to device.limits.maxTextureDimension2D. Guard against 0-size. Recreate depth texture on every resize.

Cross-Browser Compatibility The engine detects the browser via detectGpuPlatform() in GpuDevice.js and applies per-browser workarounds:

Browser Platforms Backend Notes
Chrome 113+Windows (D3D12), macOS (Metal), ChromeOS (Vulkan)Dawn (C++)SharedTextureMemory D3D11 bug on Windows only. Chrome 140+ consumes adapter on requestDevice.
Chrome 144+Linux (Vulkan, Intel Gen12+, expanding AMD/NVIDIA)DawnVulkan backend. No D3D11 swap chain issues. 2× faster writeBuffer/writeTexture.
Chrome 121+Android 12+ Qualcomm/ARM (Vulkan)DawnLower limits than desktop. Samsung Internet 24+ also supported. OpenGL ES compat via Chrome 135+ flag.
Edge 113+Same as ChromeDawnIdentical to Chrome (Chromium engine).
Firefox 141+Windows (D3D12); macOS ARM64 145+ (Metal)wgpu (Rust)Linux/Android expected 2026. No SharedTextureMemory errors. preventDefault may be no-op.

Per-Browser Workarounds (detectGpuPlatform())

  • safeCanvasUsage — RENDER_ATTACHMENT | COPY_SRC on Safari/iOS (no COPY_DST), full flags on Chromium/Firefox
  • adapterInfo — prefers device.adapterInfo (Chrome 132+), falls back to adapter.info (spec standard)
  • devicePixelContentBoxSize — pixel-perfect sizing on Chrome/Firefox, falls back to contentBoxSize × dpr on older Safari
  • context.unconfigure() — wrapped in try-catch for browsers that don't support it
  • Optional features (timestamp-query, float32-filterable, etc.) — gracefully skipped if adapter doesn't support them

Testing Device Loss

  • recovery.simulateLoss() — calls device.destroy() with a flag to trigger recovery
  • about:gpucrash — open in a separate tab to kill Chrome's GPU process (more realistic)
  • Chrome flags: --disable-domain-blocking-for-3d-apis --disable-gpu-process-crash-limit

Engine config (engine.cfg)

Definition Lightweight configuration system in engine/config that merges default engine settings with optional per-scene engine.cfg YAML files.

Example 
import { Config } from "engine/EngineImports.js";

// At scene startup
const cfg = await Config.loadEngineConfig({
  configUrl: "./engine.cfg", // relative to the scene entry
  logger,
});

// Apply cfg.room, cfg.physics, cfg.render, cfg.spawn to scene variables
