# Ambient Studio

Ambient Studio is the built-in live wallpaper editor for WebGPU OS. Its Create workspace places the live wallpaper beside material, motion, and spatial controls. The shared collection includes native materials, illustrated worlds, particles, media templates, and the original desktop backgrounds. Nodes, restricted WGSL, revisions, and reversible desktop testing remain available. (Sources: `webgpu-os/factory/apps/ambient-studio/AmbientStudioApp.js`, `webgpu-os/factory/apps/ambient-studio/AmbientStudioWorkspace.js`.)

## Create a wallpaper

Open **Ambient Studio** from the creative app group, then follow this workflow:

1. Browse **Library**, filter by category, or favorite a wallpaper.
2. Open it in **Create**, then adjust its material and motion. Native, spatial, and layered wallpapers offer **Still**, **Ambient**, or **Expressive**. Static classics identify themselves as static; Live 3D World offers simulation preview pause and resume.
3. For your own artwork, import an image or video and select a spatial interaction. Use **Depth lab** to prepare depth and protected structure.
4. Use **Nodes**, **Code / Plan**, and **Preview** for advanced authoring and inspection.
5. Save a draft or revision. **Test on Desktop** is reversible; **Use as Wallpaper** saves the active selection.

Connected components determine the rendered source. Deleting or disconnecting a component removes its contributions; restoring its code and connections recreates it. A lamp or planet can own several contributions, including geometry, light, shadows and reflections. **Duplicate component** copies a WGSL component's parameters and code and connects inputs that accept multiple contributions. Inputs that accept only one contribution require replacement wiring. The node inspector provides separate WGSL editors for each contribution. Templates and the add-node library are saved in the project, so compilation does not depend on a hidden preset inventory. Older two-node native projects offer **Expand component nodes**; loading them alone preserves their existing topology and custom source. (Sources: `webgpu-os/factory/apps/ambient-studio/AmbientNativeComposition.js`, `webgpu-os/factory/apps/ambient-studio/AmbientWallpaperV2Catalog.js`, `webgpu-os/factory/apps/ambient-studio/AmbientIllustratedComposition.js`, `webgpu-os/factory/apps/ambient-studio/AmbientStudioApp.js`.)

Native simulation nodes retain the bounded compute kernels and GPU resource declarations. Graph-authored render functions can read simulation state and change its appearance. Ink, chrome, ripple and quantum response nodes additionally own pure interaction functions: they receive pointer, press, dwell, click and local state values, then return changes for the existing solver to apply. Editing their code changes the response; disconnecting them substitutes neutral behavior. These functions cannot replace bindings or access GPU resources directly. Imported photos and videos remain media assets: objects photographed inside an image are not automatically separate geometry. Imported PLY and SPLAT data likewise remain canonical cloud assets, without automatic object separation. Procedural scatter nodes expose the generated population rather than creating one editor card for every particle. (Sources: `webgpu-os/kernel/schema/AmbientNativeAppearance.js`, `webgpu-os/kernel/schema/AmbientRuntimeV3Contract.js`, `webgpu-os/factory/apps/ambient-studio/AmbientNativeLaneComposition.js`, `webgpu-os/factory/apps/ambient-studio/AmbientSpatialGraph.js`.)

### Author motion and interaction

New native wallpapers store **Authored motion and pointer looks** as JSON on their rendering node. Expand that node's controls in Create, then select **Edit motion looks in Nodes**. Each Ambient or Expressive look contains exact values targeting editable node controls. Spatial and layered templates store their corresponding profiles in project source and target their actual motion, camera or layer controls. Switching looks applies those saved values; editing controls in the active look preserves those edits when switching away and back. Still suspends motion and input while retaining the authored controls. Older documents without profiles retain their existing compatibility behavior. (Sources: `webgpu-os/factory/apps/ambient-studio/AmbientStudioMotion.js`, `webgpu-os/factory/apps/ambient-studio/AmbientWallpaperV2Catalog.js`, `webgpu-os/factory/apps/ambient-studio/AmbientSpatialProject.js`, `webgpu-os/factory/apps/ambient-studio/AmbientShaderWorkbench.js`, `webgpu-os/factory/apps/ambient-studio/AmbientV2Examples.js`.)

For example, this complete `motionLooks` value gives a native rendering node two distinct speeds and pointer strengths. `$self` addresses that rendering node; use a component's actual node ID to target its response controls instead. Values must satisfy the targeted control's type and bounds.

```json
{
  "version": 1,
  "ambient": {
    "interactive": true,
    "values": [
      { "target": { "kind": "node", "id": "$self", "property": "params.speed" }, "value": 0.2 },
      { "target": { "kind": "node", "id": "$self", "property": "params.pointerInfluence" }, "value": 0.15 }
    ]
  },
  "expressive": {
    "interactive": true,
    "values": [
      { "target": { "kind": "node", "id": "$self", "property": "params.speed" }, "value": 0.35 },
      { "target": { "kind": "node", "id": "$self", "property": "params.pointerInfluence" }, "value": 0.4 }
    ]
  }
}
```

Pointer and click expressions belong to the saved response code. Removing a response removes its hover, press and click contributions together. Turning input off discards pending clicks so resuming cannot replay a disabled gesture. Static classic backgrounds remain static unless their authored source changes. (Sources: `webgpu-os/factory/apps/ambient-studio/AmbientMaterialComposition.js`, `webgpu-os/factory/apps/ambient-studio/AmbientStudioApp.js`, `webgpu-os/kernel/drivers/AmbientRuntimeV3FrameInputs.js`.)

## Understand node and runtime support

Ambient Studio separates authoring vocabulary from installed runtime capability. The node library labels that difference instead of showing a successful compile badge for content the runtime cannot draw.

| Composite V2 support | Nodes | Current behavior |
| --- | --- | --- |
| Executable | `source.shader`, `source.showcase`, `effect.color-grade`, `effect.blur`, `effect.bloom`, `layer.compose`, `output.wallpaper` | Compiles into ordered procedural layers. Effects run only on one procedural source at a time and remain inside a bounded shader sample budget. |
| Executable shader contributions | `code.wgsl.*` connected to a composed `source.shader` | Compiles persisted source contributions into that shader's saved template. |
| Implicit signals | `input.time`, `input.pointer` | Records the bounded runtime dependency. The procedural runtime owns the corresponding live signal contract. |
| Executable media | `source.image`, `source.video` | Verified project assets render through native texture layers with fit, placement, opacity, and muted video playback. Old descriptors without complete asset records require reopening and saving. |
| Runtime pending | `input.audio`, `effect.parallax`, all `particle.*`, `voxel.*`, and `scene.*` nodes | The required composite runtime ABI or compiler is not installed. A required unsupported node fails compilation before preview or desktop activation. |

The node library displays **RUNTIME PENDING** on unsupported authoring nodes. Classic Living Matter and Voxel Shrine retain their dedicated particle and scene implementations. Spatial Gaussian projects use their own geometry, source, processing and output graph with a shared preview/desktop driver. Native V3 component graphs execute through their corresponding program, simulation or particle-field driver. (Sources: `webgpu-os/factory/apps/ambient-studio/AmbientCompositeCompiler.js`, `webgpu-os/kernel/drivers/WebGPUCompositeAmbientDriver.js`, `webgpu-os/factory/apps/ambient-studio/AmbientSpatialProject.js`, `webgpu-os/factory/apps/ambient-studio/AmbientWallpaperV2Catalog.js`.)

## Import assets and portable packages

Layered V2 projects accept these local, self-contained assets:

- PNG, JPEG, WebP, and GIF images.
- MP4 and WebM video.
- Ogg, MP3, and WAV audio.
- Binary GLB models with no external texture or buffer references.

Layered import checks the declared type, file extension, magic bytes, decode metadata, size, dimensions, duration, and SHA-256 digest. It rejects active document and script formats. Image and video layers now execute in the composite renderer. Spatial source imports accept PNG, JPEG, WebP, MP4, and WebM through that same validator, up to 256 MiB. A missing browser MIME type can use the extension, but the bytes must still match. Decoding has a bounded timeout and cancellation; a newer import or project change retires the earlier operation. Original bytes, dimensions, video duration and full content identity remain stored. Gaussian PLY and SPLAT files become canonical geometry. (Sources: `webgpu-os/factory/apps/ambient-studio/AmbientAssetImporter.js`, `webgpu-os/factory/apps/ambient-studio/AmbientSpatialTools.js`, `webgpu-os/kernel/drivers/AmbientCompositeMedia.js`.)

A V2 export uses the `.ambient` extension and `application/vnd.particle-realms.ambient+zip` media type. The package contains `ambient-package.json`, `project.ambient.json`, and only declared content-addressed assets. Vertex depth comes from the actual rendered bed below the mean water level; pigment endpoints blend in linear light before encoding into the existing mesh colors. The mesh pipeline interpolates those encoded vertex colors before fragment decoding. Saved `roughness` controls engine GGX highlights and eight deterministic weighted sky samples with projected-footprint filtering. This is an opaque depth-pigment and sampled-sky approximation, not physical transmission, PDF-correct environment integration, refraction, scene-object reflection, screen-space reflection or a fluid solve. Absent or `plain` keeps the original surface arrays and optics. The new Forest presence factory explicitly saves the depth profile; old projects are not migrated. (Sources: `webgpu-os/factory/apps/ambient-studio/spatial/SpatialDioramaSchema.js`, `webgpu-os/factory/apps/ambient-studio/spatial/SpatialDiorama.js`, `webgpu-os/kernel/drivers/SpatialAmbientLane.js`, `webgpu-os/kernel/drivers/SpatialAmbientShaders.js`, `tests/ambient-spatial-rendering.test.js`, `tests/ambient-spatial-rendering-native.test.js`.)

Optional terrain `materialScale` controls the frequency of existing soil/vegetation pigment patches. The fresh forest saves 0.2 for broader variation and a saved ground detail multiplier of 0.5 for less fine grain. Changing patch frequency preserves the original erosion field, terrain triangles, normals and channel grading. Missing or 1 retains earlier pigment output. Create's **Editable scene parts** controls use the same node parameter handler as the graph inspector; merely displaying optional defaults does not write them into an older project. (Sources: `webgpu-os/factory/apps/ambient-studio/spatial/SpatialDiorama.js`, `webgpu-os/factory/apps/ambient-studio/spatial/SpatialDioramaSchema.js`, `webgpu-os/factory/apps/ambient-studio/AmbientSpatialProject.js`, `webgpu-os/factory/apps/ambient-studio/AmbientImmersionControls.js`, `tests/ambient-immersion-integration.test.js`.)

Optional renderer version 1 adds projected-footprint texture filtering and mipmaps, conservative frustum/opacity culling and a subpixel threshold that retains elongated thin structures. **GPU cull and sort** uses bounded bitonic depth sorting and an indirect draw with stable ID ties. **CPU tile ray order** estimates Gaussian maximum-density depth on each of sixteen tile-center rays; it requires CPU visibility. Tile ordering is an approximation, not per-pixel visibility or a guaranteed removal of all transparency popping. CPU visible counts are measured during preparation; production GPU counts stay unavailable without a readback. (Sources: `webgpu-os/factory/apps/ambient-studio/spatial/SpatialRenderingOptions.js`, `webgpu-os/kernel/drivers/SpatialAmbientMipmaps.js`, `webgpu-os/kernel/drivers/SpatialAmbientGpuVisibility.js`, `webgpu-os/kernel/drivers/SpatialAmbientVisibility.js`, `webgpu-os/kernel/drivers/SpatialAmbientLane.js`.)

Opaque generated meshes write depth before the splats. **Generated sky & surface materials** saves sky colors, sun color and intensity, a sun disc and halo, directional cloud coverage and advection, filtered bark and ground detail, shared roughness and surface highlights. Generated surfaces use the saved sun and an approximation of sky hemisphere illumination. The sky reuses engine noise, sun and atmospheric phase functions; its directional cloud layer is not a volumetric cloud simulation. Distance and height fog share world-space parameters with the splats. The tree controls include species selection and independent dimensions, material colors and wind values. (Sources: `webgpu-os/factory/apps/ambient-studio/AmbientImmersionControls.js`, `webgpu-os/factory/apps/ambient-studio/spatial/SpatialRenderingOptions.js`, `webgpu-os/factory/apps/ambient-studio/spatial/SpatialDioramaSchema.js`, `webgpu-os/kernel/drivers/SpatialAmbientShaders.js`.)

**Opaque geometry sun shadows** opts generated meshes into the engine's `ShadowMapPass`. A directional depth map and 3Ã—3 percentage-closer filtering cast shadows from actual opaque geometry, including solid leaves, onto actual depth-writing surfaces. Water receives these shadows but is excluded from the caster pass; a water-only scene allocates no shadow resources. The same saved sun direction and mesh wind transform drive the main and shadow passes. Shadow strength defaults to zero; **Geometry shadow resolution** selects 256, 512, 1024 or 2048 pixels, and **Geometry shadow depth bias** controls depth comparison bias. Shadows apply only to the color view; diagnostic depth, normal and group views keep their encoded values. The spatial adapter disables the editor's implicit ground-plane receiver. Its opaque-surface variant loads scene depth through a float texture binding to meet compatibility-mode depth-load restrictions; the engine's default shader retains its existing behavior. Transparent Gaussian splats render after the shadow composite and neither cast nor receive these mesh shadows. This is a single directional map without cascades, transparent foliage shadows or global illumination. (Sources: `engine/render/passes/ShadowMapPass.js`, `webgpu-os/kernel/drivers/SpatialAmbientShadows.js`, `webgpu-os/kernel/drivers/SpatialAmbientLane.js`, `webgpu-os/factory/apps/ambient-studio/spatial/SpatialRenderingOptions.js`.)

Sky, materials, fog and shadow controls are saved graph values and survive project JSON, portable export and the shared desktop renderer. They provide authored surface depth and atmospheric recession; they do not turn generated geometry into a measured captured scene. (Sources: `webgpu-os/factory/apps/ambient-studio/AmbientSpatialGraph.js`, `webgpu-os/kernel/drivers/SpatialAmbientLane.js`.)

Native captures show the forest's stream in the default view and preserve separate tree, foliage and bank depth under left, right, translated, close and rear viewpoints. Lateral foliage attachments and varied crown directions improve the foreground trees modestly; localized dry vegetation and broader ground pigment patches improve near-bank composition. The river saves roughness 0.45 and glint 0.65 for a calmer, darker treatment. The pilot remains stylized: sparse repeated tree forks, wispy pine needles, coarse terrain silhouette and approximate water optics still limit realism. These captures demonstrate editable procedural 3D presence, not photographic accuracy or recovery of a photographed tree's hidden surfaces. (Sources: `artifacts/ambient-quality-review/realm-presence-journey-20261001-r02/report.json`, `artifacts/ambient-quality-review/realm-presence-independent-review-20261001-r01.md`.)

A controlled comparison identifies the broad transverse creek bands as opaque tree shadows: setting shadow strength to zero removes them, while setting wave height to zero preserves them. The existing shadow composite darkens the whole accumulated water radiance, including reflected sky. It does not separate direct-light visibility from environment reflection. This is a current rendering approximation, rather than evidence of wave ringing. The diagnostic changes are saved comparison projects; the factory keeps its authored shadows. (Sources: `webgpu-os/kernel/drivers/SpatialAmbientShadows.js`, `engine/render/passes/ShadowMapPass.js`, `artifacts/ambient-quality-review/realm-presence-water-shadow-20261001-r03/report.json`.)

### Surface textures and saved looks

**Surface textures & styles** exposes separate ground, bark and stone controls for texture scale, detail amount, roughness and highlights, plus shared bump strength and thin-leaf backlighting. These are optional fields in the existing `spatial.appearance` node. Each new multiplier defaults to 1; absent fields retain earlier rendering. Texture coordinates and bump dimensions use world scene units, which are metres for the forest's metric frame with unit scale 1. Larger texture-scale multipliers produce finer grain. Non-neutral ground frequencies filter individual noise octaves, and unresolved stone/bark grain fades with projected footprint. Bump changes shading normals; diagnostic normals retain the original geometry. Soft painted removes generated surface lighting and bump; Satin adjusts generated surface roughness and highlights. The controls retain the selected capture profile and original source pixels, UVs, opacity and calibration. **Reset texture adjustments** restores the new multipliers independently. Removing or disconnecting the appearance node removes its overrides. Existing nonspatial materials continue to use their editable native material contributions. (Sources: `webgpu-os/factory/apps/ambient-studio/spatial/SpatialRenderingOptions.js`, `webgpu-os/factory/apps/ambient-studio/AmbientImmersionControls.js`, `webgpu-os/factory/apps/ambient-studio/AmbientMaterialComposition.js`, `tests/ambient-immersion-integration.test.js`.)

The stone option changes only owned rock material IDs, preserving geometry, pigment, identities and placement. Ordinary material 0, captured radiance, leaves and water retain their existing material behavior. ### Reuse PAI and OCR primitives without changing their meaning

The engine's deterministic RGBA/luminance helpers and exact image-to-source transforms are reusable foundations for future owned depth work. `TensorSpatialMath` already provides bounded spatial patches, pooling and their gradients. The existing handwriting encoder uses these operations for shared three-row stroke filters on 32-pixel-high strips; it is not a scene-depth decoder. PAI's current image observation is an 8Ã—8 luminance summary, while its joint conditioning and Ouroboros recurrence operate on learned context states. Those paths do not currently produce dense calibrated depth or hidden three-dimensional geometry. Ambient rendering and stereo preparation do not require PAI serving. (Sources: `engine/core/math/ImageMath.js`, `engine/core/math/TensorSpatialMath.js`, `agi/vision/SpatialHandwritingEncoder.js`, `agi/soul/Observation.js`, `agi/soul/PaiGPU.js`.)

OCR's document routines intentionally whiten page edges, rectify planar pages, identify ink regions and prepare glyphs. Applying that preprocessing to wallpaper source colors would change the artwork; an ink mask is not a semantic tree or object mask. Reuse the pixel and transform primitives while retaining original RGBA and explicit calibration. A future learned depth head would need its own dense prediction, scale, confidence, training and verification contracts. It is not an installed capability of the OCR or PAI models. (Sources: `engine/core/math/DocumentImageMath.js`, `engine/core/math/DocumentRegionMath.js`, `engine/core/math/DocumentQuadMath.js`, `webgpu-os/factory/components/ocr/worker.js`, `webgpu-os/factory/components/ocr/perspective.js`.)

## Shader authority boundary

Authored WGSL cannot own an entry point, bind group, binding, uniform or storage address space, workgroup state, extension, unbounded loop, or storage side effect. It defines the existing pure `paintShader` function for composite/V1 shaders or `paintAmbient` function for native programs. Shared contracts validate authority and bounds before persistence and GPU compilation; WebGPU validates shader types and syntax. (Sources: `webgpu-os/kernel/schema/AmbientProgramContract.js`, `webgpu-os/kernel/schema/AmbientRuntimeV3Contract.js`.)

Native stateful and particle-field wallpapers also accept graph-authored appearance functions. These replace existing render-function bodies with the same signatures or add pure helpers; the renderer retains its entry points, compute kernels and bindings. This keeps props and their visual contributions editable while preserving the runtime's GPU ownership. (Source: `webgpu-os/kernel/schema/AmbientNativeAppearance.js`.)

Ambient packages cannot turn assets into code. The importer rejects HTML, JavaScript, ECMAScript, SVG, active filename extensions, external URL references, and undeclared ZIP entries. Package verification provides content integrity inside the operator's project library; it does not claim publisher identity or a package signature. (Source: `webgpu-os/factory/apps/ambient-studio/AmbientPackage.js`.)

## Accessibility and performance

The app uses semantic buttons, labeled tabs and dialogs, keyboard shortcuts, focus restoration, live status announcements, reduced-motion behavior, forced-color support, and container-based layouts down to the 560-pixel minimum app width. Each project also records a static color fallback. (Sources: `webgpu-os/factory/apps/ambient-studio/AmbientStudioApp.js`, `webgpu-os/factory/apps/ambient-studio/AmbientProjectV2.js`.)

The desktop drivers cap frame rate, device-pixel ratio, texture dimensions, and total pixels. They stop or suspend continuous frames when the runtime is hidden, paused, or subject to reduced-motion policy. Invalid recompiles retain the last known good plan or expose a truthful fallback and diagnostic. (Sources: `webgpu-os/kernel/drivers/WebGPUAmbientProgramDriver.js`, `webgpu-os/kernel/drivers/WebGPUCompositeAmbientDriver.js`.)

Selecting Live 3D World while playback is paused submits one bounded still frame without physics or grid updates and without registering a continuous producer. Forced colors submits its cleared fallback without particles. A confirmed still frame can complete activation without enabling motion. Ambient Runtime V3 reuses pending compilation for repeated updates to the same plan and applies the latest host pause and accessibility settings before the initial frame. (Sources: `engine/sim/particles/ambient/ParticleAmbientRuntime.js`, `webgpu-os/kernel/drivers/WebGPUAmbientRuntimeV3Driver.js`.)

Settings exposes manual pause and optional pause policies for covered OS windows, app fullscreen and battery use. Covered-window detection samples the union of visible WebGPU OS windows; it cannot inspect native Windows applications. Battery controls are unavailable when the browser does not expose battery status. Pause causes combine, so releasing one cause cannot resume another. The gallery reports measured submitted-frame cadence, backing resolution, owned resource counts and available coordinator CPU encode time. GPU timing stays unavailable rather than presenting an unmeasured zero. (Sources: `webgpu-os/kernel/AmbientPlaybackPolicy.js`, `webgpu-os/kernel/AmbientEngine.js`, `webgpu-os/shell/Desktop.js`, `webgpu-os/kernel/ThemeEngine.js`.)

Motion looks apply each project's saved target values. **Still** disables interaction and continuous motion while preserving edits; **Ambient** and **Expressive** restore their separate authored controls. Older documents without profiles retain their previous scaling behavior. Generated classic gradients stay static, and Live 3D World retains its native simulation controls. (Sources: `webgpu-os/factory/apps/ambient-studio/AmbientStudioMotion.js`, `webgpu-os/factory/apps/ambient-studio/AmbientStudioWorkspace.js`.)

## Design inspiration

Ambient Studio combines proven interaction patterns without cloning another editor:

- Shadertoy's immediate full-screen feedback and small stable input vocabulary inform the live `color`, `uv`, `depth`, and `time` contract. The OS uses WGSL and normalized coordinates rather than accepting GLSL `mainImage`, global bindings, or arbitrary channels. [Shadertoy input reference](https://help.maxon.net/ag/en-us/Content/html/Modifier_image_shadertoy.html)
- Pixel Composer's typed junctions, procedural composition, direct property animation, and timeline inform node wiring and keyframes. Ambient Studio reuses OS graph and shader contracts instead of importing a second execution engine. [Pixel Composer](https://pixel-composer.com/), [Pixel Composer node workflow](https://pixel-composer-doc.readthedocs.io/en/latest/node/)
- Unity Shader Graph's separated Blackboard, Graph Inspector, and Main Preview inform the editor, inspector, and full preview split. [Unity Shader Graph window](https://docs.unity3d.com/Packages/com.unity.shadergraph@10.0/manual/Shader-Graph-Window.html)
- Blender's shader editor and reusable node-group model inform a possible reviewed subgraph phase. Recursive user groups and arbitrary multi-pass feedback are not part of the current execution contract. [Blender Shader Editor](https://docs.blender.org/manual/en/4.4/editors/shader_editor.html), [Blender node groups](https://docs.blender.org/manual/en/4.0/interface/controls/nodes/groups.html)
