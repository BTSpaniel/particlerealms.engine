# Particle Realms Engine

Build browser games, simulations, and interactive tools with Particle Engine and Plauna UI. The Engine supplies WebGPU rendering, ECS, simulation, physics, audio, and networking. The Platform adds Editor, AGI, and WebGPU OS.

**Browser-native JavaScript. Python tooling. No npm application dependencies.**

[Download packages](https://github.com/BTSpaniel/particlerealms.engine/releases) · [Live platform](https://particlerealms.online/) · [Learn](https://particlerealms.online/learn/) · [Playground](https://particlerealms.online/playground/) · [Documentation](https://particlerealms.online/guide/)

## Run an SDK

Inside the extracted Engine or Platform SDK directory:

```powershell
python serve_sdk.py --port 9002 --isolate
```

Open **<http://127.0.0.1:9002/>**. The landing page checks the compiled runtime and links its source and compiled examples and offline documentation. The server uses Python's standard library and binds to localhost.

**Do not double-click `index.html`.** Browser modules and runtime fetches require HTTP; `file://` causes CORS failures. Use a current browser with a working WebGPU adapter. Public hosting requires HTTPS. `--isolate` supplies the headers needed for threaded compute and `SharedArrayBuffer` and may be omitted for other workloads.

Base SDK examples cover rendering/ECS/native physics, a real Surface Field worker, and Plauna interaction. Platform adds Editor save/reopen, AGI GPU computation, and explicit OS boot with a local app. Each example reports measured checks and provides a **Release resources** action.

Open `MD/viewer/?doc=guides/sdk-distribution.md` on the local server or read `MD/guides/sdk-distribution.md` in the package for complete setup and hosting instructions.

## Start an app with the Template

Inside the directory where you extracted `Template.zip`:

```powershell
python serve.py 9002
```

Open <http://127.0.0.1:9002/>. Windows users can also run `launch.bat --port 9002`. The default Template port is 8000.

Choose **WebGPU OS**, **Plauna Showcase**, or **Blank Canvas**. Blank Canvas reveals your application host after runtime verification; your app creates its canvas and owns the frame loop and cleanup. See the included `README.md` for its boot contracts. Use an SDK for canonical source imports or self-contained rebuilding.

## Source modules and compiled APIs

In an SDK application at the package root, source mode uses canonical public entry points:

```javascript
import { createWorld, createEntity } from './engine/EngineBootstrap.js';

const world = createWorld({ name: 'My application' });
const entity = createEntity(world);
```

Plauna UI exports are available from `plauna/index.js` in both SDKs.

Compiled mode uses the loader tag supplied in the compiled example, preserving its paths and metadata:

```javascript
const PE = await globalThis.__PE_RUNTIME_READY;
const world = PE.createWorld({ name: 'My application' });
const entity = PE.createEntity(world);
```

Base exposes `PE.Plauna`; Platform also exposes `PE.AGI`, `PE.Editor`, and `PE.WebGPUOS`. OS boot is explicit. Keep the loader, executor, manifest, compression parts, workers, and native assets together when hosting an app. The SDK guide explains source imports beneath nested URLs, public entry points, and experimental capabilities.

## Rebuild the JavaScript runtime

Both SDKs include their bundler and build inputs. Use the exact environment specified by `sdk-build.json`: the initial baseline is **Python 3.12.7**, pinned Python dependencies, **rjsmin 1.2.5**, and the recorded native compression backends.

Install dependencies explicitly before an offline build:

```powershell
python -m pip install -r requirements-sdk.txt
python bundle_engine.py --sdk-rebuild
```

Outputs are `build/runtime` and the complete `build/engine-sdk` or `build/platform-sdk`, with a ZIP beside the SDK directory. The descriptor preserves the included subsystems. Rebuilds do not download tools. Installed Chromium is required for browser acceptance.

This rebuilds JavaScript using the supplied, verified WASM. Recompiling PhysX, Blast, Flow, or Rust kernels is a separate native-toolchain workflow. No private signing keys are included or required. Changing signed-owner inputs requires an authorized replacement public package whose signature, validity, payloads, and owner identities pass verification. The SDK guide documents that workflow.

## Validation and artifact identity

The release includes [SHA256SUMS](https://github.com/BTSpaniel/particlerealms.engine/releases/download/v0.8.1-alpha.1/SHA256SUMS) and [SDK-VALIDATION.json](https://github.com/BTSpaniel/particlerealms.engine/releases/download/v0.8.1-alpha.1/SDK-VALIDATION.json). Verify the archive hash before extraction. On Windows, run `Get-FileHash .\particle-engine-sdk.zip -Algorithm SHA256` and compare it with `SHA256SUMS`.

Each SDK's `manifest.json` inventories its files, build inputs, public entry points, tool versions, and validation results. Its runtime manifest records byte counts and SHA-384 integrity; the accompanying in-toto/SLSA provenance statement records input and output identities. Keep these receipts with the runtime.

SDK acceptance checks extraction outside the development repository, root and nested hosting, source and compiled examples, worker operations, native assets, cleanup, and unsupported-browser diagnostics. Offline rebuilding checks two identical builds in a pinned environment and verifies that an authored Engine CPU change executes in the rebuilt runtime. These are package checks; they do not qualify every repository test or experimental API.
